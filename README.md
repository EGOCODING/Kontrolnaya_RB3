## О проекте

Многостраничный сайт магазина техники TechShop на чистом HTML/CSS. Основа проекта
перенесена из контрольной работы №1 (HTML/CSS-проект), Bootstrap не используется:
вся сетка построена на Flexbox и CSS Grid, адаптивность — на медиазапросах.

Страницы:

| Страница | Содержит |
| --- | --- |
| `index.html` | hero-блок, преимущества, популярные товары |
| `catalog.html` | сетка карточек, боковой фильтр категорий |
| `product.html` | карточка товара, таблица характеристик |
| `order.html` | форма заявки и сводка заказа |
| `contacts.html` | контактная информация и форма обратной связи |

## Адаптивные решения

- добавлен отдельный файл `css/responsive.css`, он подключён **после** `css/style.css`
  на всех пяти страницах, поэтому адаптивные правила переопределяют базовые;
- на каждой странице есть `meta name="viewport" content="width=device-width, initial-scale=1.0"`;
- применён подход **Mobile First**: `style.css` описывает мобильную версию
  (одна колонка, крупные элементы), а `responsive.css` расширяет её через `min-width`;
- медиазапросы: `640px`, `768px`, `1024px`, `1280px`, `1440px`, `1600px`,
  а также `prefers-reduced-motion` и `prefers-contrast`;
- **навигация**: до `767px` — кнопка-гамбургер с выпадающей панелью, с `768px` —
  горизонтальное меню; состояние кнопки передаётся через `aria-expanded`,
  подпись меняется на «Открыть меню» / «Закрыть меню», панель закрывается по `Esc`
  и после выбора пункта;
- **hero-блок**: по центру в одну колонку на мобильном, с `1024px` — CSS Grid
  из двух колонок (заголовок и текст слева, кнопки справа), размеры шрифта
  растут по breakpoint-ам;
- **сетка карточек** (`Grid`): 1 колонка → 2 (`640px`) → 3 (`1024px`) →
  4 (`1440px`) → 5 (`1600px`), промежутки увеличиваются вместе с экраном;
- **каталог и фильтр**: на мобильном фильтр — горизонтальная лента чипов
  с прокруткой внутри блока, с `768px` — липкий (`position: sticky`) боковой
  сайдбар 200–280px; у колонок сетки задан `min-width: 0`, чтобы содержимое
  не растягивало страницу;
- **страница товара**: одна колонка на мобильном, с `768px` — две колонки
  (изображение / информация), на `1024px` пропорции 1.15fr / 1fr;
- **таблица характеристик**: до `768px` превращается в карточное представление
  (`tr`, `th`, `td` — блоки, подписи над значениями), с `768px` — обычная
  таблица с `min-width: 640px`; контейнер `.table-wrapper` имеет
  `overflow-x: auto` и `-webkit-overflow-scrolling: touch`, поэтому при нехватке
  места прокручивается только таблица, а не страница;
- **формы**: на мобильном все поля в одну колонку и на всю ширину, кнопка
  отправки тоже на всю ширину; с `640px` поля группируются в две колонки
  (`.form-row` на Grid), кнопка становится компактной; высота полей не меньше
  `44px`, шрифт `16px` — чтобы iOS не масштабировал страницу при фокусе;
- **подвал**: 1 колонка → 2 (`768px`) → 4 (`1024px`);
- **модальное окно**: ширина ограничена `100%` минус отступы, `max-height: 90vh`
  и внутренняя прокрутка, уменьшенные отступы на мобильном;
- **responsive images**: базовое правило `img, video { max-width: 100%; height: auto; }`,
  у карточек `aspect-ratio: 4 / 3` и `object-fit: cover`, заданы `width`/`height`
  (нет скачков вёрстки), `loading="lazy"` для карточек каталога; для каждого товара
  подготовлены версии `480w`, `640w`, `960w`, подключённые через `srcset` + `sizes`;
  для главного изображения на страницах `index.html` и `product.html` используется
  `<picture>` с WebP и JPEG-фолбэком;
- **отсутствие горизонтального скролла**: ни один блок не имеет фиксированной ширины
  больше экрана, длинные слова переносятся (`overflow-wrap: break-word`),
  изображения ограничены контейнером, прокрутка возможна только внутри
  `.table-wrapper` и ленты фильтров.

## Доступность

- на всех страницах добавлена ссылка пропуска к основному содержимому
  (`.skip-link`), у `<main>` есть `tabindex="-1"`, поэтому фокус действительно
  переходит к контенту;
- на каждой странице ровно один `<h1>`, заголовки идут по порядку `h1 → h2 → h3`;
- навигация размечена через `<nav aria-label="Основная навигация">`, текущая
  страница помечена `aria-current="page"`; ссылки и кнопки используются по назначению
  (переходы — ссылки, действия — `button`);
- видимый фокус: `:focus-visible` с контуром 2px и отступом, у полей формы — рамка
  и контур; в режиме `prefers-contrast: more` контур толще;
- у всех полей формы есть связанные `<label for>`, подсказки связаны через
  `aria-describedby`, обязательные поля помечены и в тексте, и атрибутом `required`;
- у всех изображений осмысленный `alt`, декоративных картинок без описания нет;
- исправлена контрастность: вторичный текст (зачёркнутые цены, подвал, подсказки)
  был `#a3a3a3` (≈2.5:1) — заменён на `#6b6b6b` (≈5.3:1); зелёный бейдж «Хит» —
  `#059669` → `#047857`; рамки полей и кнопок получили `#8c8c8c` (не менее 3:1
  для границ элементов управления);
- модальное окно доступно с клавиатуры: `role="dialog"`, `aria-modal="true"`,
  `aria-labelledby`, фокус переводится на первое поле, Tab и Shift+Tab удерживаются
  внутри диалога, `Esc` закрывает окно, после закрытия фокус возвращается
  на кнопку, которая его открыла;
- фильтры каталога сообщают состояние через `aria-pressed`, сообщения об успешной
  отправке — через `role="status"` и `tabindex="-1"` (фокус переводится на сообщение);
- `aria-*` используется только там, где нет нативного HTML-решения;
- учтён `prefers-reduced-motion: reduce` — анимации и плавная прокрутка отключаются.

клавиатурная доступность и порядок табов, видимый фокус, ловушка фокуса в диалоге,
семантические ориентиры (`header`/`nav`/`main`/`footer`), скрытие невидимого
контента от скринридеров.

Как повторить:

```bash
npx lighthouse http://127.0.0.1:8099/index.html \
  --only-categories=accessibility \
  --output=html --output-path=./lighthouse/index-accessibility-report.html
```

## Проверенные ширины

Проверка выполнялась в браузере на всех пяти страницах. Для каждой ширины
измерялась ширина документа: горизонтального скролла нет, если
`documentElement.scrollWidth` равен `clientWidth`.

| Ширина | Режим | Что проверялось | Результат |
| --- | --- | --- | --- |
| 360px | мобильный | шапка и гамбургер, hero, карточки в 1 колонку, фильтр-лента, карточная таблица, форма в 1 колонку, подвал, модальное окно | скролла нет (`360 == 360`) |
| 430px | крупный мобильный | то же, крупные кнопки и поля | скролла нет (`430 == 430`) |
| 768px | планшет | горизонтальное меню, карточки в 2 колонки, липкий фильтр, таблица в классическом виде, форма в 2 колонки | скролла нет (`768 == 768`) |
| 1024px | небольшой desktop | двухколоночный hero, 3 колонки карточек, сайдбар 240px, пропорции страницы товара | скролла нет (`1024 == 1024`) |
| 1440px | широкий desktop | 4 колонки карточек, широкий контейнер 1360px, подвал в 4 колонки | скролла нет (`1440 == 1440`) |

Дополнительно проверено: на 360px модальное окно занимает 328px и помещается
в экран, изображение карточки подгружается в версии `480w` (WebP), при
увеличении ширины браузер выбирает более крупный кандидат из `srcset`.

## Самостоятельные доработки

Сверх базового задания методических указаний:

1. **Улучшенная мобильная навигация** — `aria-expanded`/`aria-label`,
   закрытие по `Esc` с возвратом фокуса на кнопку, автоматическое закрытие
   после выбора пункта, блокировка «залипания» открытой панели при переходе.
2. **Карточное представление таблицы характеристик** на мобильном вместо
   горизонтальной прокрутки: подписи характеристик переносятся над значениями,
   шапка таблицы скрывается визуально, но остаётся в разметке для скринридеров.
3. **Два варианта responsive images**: `srcset` + `sizes` для всех карточек
   и `<picture>` с WebP + JPEG-фолбэком для главных изображений.
4. **Локальные изображения** в `images/` — три размера и два формата на товар,
   поэтому страница не зависит от внешнего сервиса картинок.
5. **Адаптивный каталог сверх базового варианта**: рабочий фильтр по категориям
   (карточки скрываются атрибутом `hidden`, счётчик результатов объявляется
   через `role="status"`), фильтр-лента на мобильном и липкий сайдбар на планшете
   и десктопе, `aria-pressed` у кнопок фильтра, `min-width: 0` у колонок сетки.
6. **Живая сводка заказа**: при выборе товара в форме пересчитываются его
   название и итоговая сумма, после отправки сводка возвращается в исходное
   состояние — раньше в блоке всегда был один и тот же товар.
7. **Доступное модальное окно**: удержание фокуса внутри диалога, возврат фокуса,
   закрытие по клику на подложку и по `Esc`.
8. **Дополнительные настройки доступности**: `skip-link`, `prefers-reduced-motion`,
   `prefers-contrast`, контрастные границы полей, шрифт 16px в полях (без
   автоматического зума на iOS), `aria-describedby` для подсказок.
9. **Проверка адаптивности измерениями** — вместо визуальной оценки ширина
   документа сравнивалась с шириной окна на пяти ширинах для всех страниц.

10. **Сквозной выбор товара**: карточка каталога передаёт `?product=...`, страница товара заполняет название, цену, описание, характеристики и изображение из набора данных, а кнопка «Оформить заявку» открывает заказ с уже выбранным товаром.
